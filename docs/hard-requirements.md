# Automatic Print：用户硬性需求与新对话交接

更新时间：2026-09-13。本文整理用户明确提出的需求，不代表全部功能已通过生产验收。
发生冲突时，以用户最新明确要求为准；不要擅自恢复已废弃的规则。

## 1. 当前目标与协作方式

- 用户经营 POD（按需印刷）公司，排版错误会造成实际生产损失。
- 当前第一优先级是本地图片文件夹排版，不是 ERP 接单自动化。
- 平台接单、生产批次、本地批次管理等暂时隐藏，不删除底层功能。
- 主界面不显示“Haloo：本地有 0 个本地批次……”等平台或缓存提示。
- 用户确认实现方向后，应直接修改代码、测试和验证，不要反复只复述方案。
- 不要未经验证就说“已经解决”；单元测试通过不等于生产文件已经安全。
- 保留用户已有修改，不擅自覆盖参数、删文件、重置代码或触发不可撤销的生产动作。

## 2. 代码规范

- 一个代码文件尽量约 200 行，硬上限 250 行。
- 类似功能放在同一个功能目录，代码可复用、模块化、可维护。
- 不把 UI、平台接口、排版算法、文件处理和线程生命周期混在一个大文件中。
- UI 使用中文，界面说明文字可复制。
- 导航和设置遵循“父分类 → 子分类 → 具体记录”的层级结构。
- 父项变化时一次交互就更新合法子项，清除过期选择，不要求用户选择两遍。

## 3. 界面和参数持久化

- 主界面围绕本地排版：文件夹入口、常用标签文字、机器号、图片手动旋转、即时预览。
- 不常用配置放在打印参数中，参数入口位于主界面底部。
- 色块设置及完整的标签/文字设置属于打印参数，可以单独打开设置界面。
- 标签文字要能在主界面经常编辑；预览直接可见，不需要再点击“预览”。
- 文件夹选择默认从上次打开的位置开始。
- 用户修改的参数自动持久化，退出时补保存，下次打开恢复。
- 升级不能强制把用户已选字号、位置、膜规格等改回新的默认值。
- 主界面显示版本和检查更新入口。
- 发版不能只显示递增数字，必须同时显示固定的发版日期；日期不能取软件启动当天。同一天迭代保留版本号区分，内部更新比较继续使用数字版本号。
- 保存排版文件后自动打开保存文件夹，不让用户手动寻找。
- 桌面需要打开入口；图标使用“HA”，代表 Haloo Automatic。

## 4. 输入图片、尺寸与文件名

- 读取图片内容前，先发现并显示图片文件名，便于查看尺码、确认正在处理什么。
- 支持文件名搜索、复制及按平台规则批量改名。
- 显示图片实际打印尺寸（毫米），可靠尺寸来自图片内嵌 DPI。
- 缺少可靠 DPI 时必须提示；估算尺寸不能当作可靠切膜生产尺寸。
- 保持源图片透明度，标签不加白色底框，不能无故输出白底。
- 右侧未使用的空白不能仅为凑宽度而消耗膜；但固定分区输出不能裁掉刀位基准。

### 4.1 多件文件名整理

- 多项多件、单项多件排版前，需要按平台文件名规则去掉生产前缀。
- 删除第一个 `-` 之前的全部字符，包含该 `-`。
- 示例：`CVC面料00004-BJRCCCQ-1-...` → `BJRCCCQ-1-...`。
- 隆丰示例：`A0000007-订单编码-...`，删除 `A0000007-`。
- 不只支持 CVC 或隆丰；以后同类平台也使用这个逻辑。
- 必须避免错误识别：已经去过前缀的文件不能再次删除订单编码。
- 同订单、同颜色的图片，尺码从小到大排序，不能按普通字母顺序排序尺码。

## 5. 生产安全：订单和双面不能散

- 同一多件订单必须保持成组、相邻，不能散到不连续的生产位置。
- 蜂鸟编码 `...-NO1-1` 与 `...-NO1-2` 表示同件商品的正反面。
- 双面两张图必须相邻：常规区可以横向并排或纵向紧邻。
- 转移到旋转区时按完整订单组转移，不能只拿其中一张正面、背面或某件商品。
- 合并几个批次排版时也必须保留订单、双面和尺码排序约束。
- 无法可靠识别订单归属时，不得乐观地把可能属于同订单的图片拆散。

## 6. 膜规格、间距和材料利用率

- 生产膜规格有 45cm 和 60cm。
- 当前默认是 60cm（600mm）、固定双列，不再默认 45cm。
- 图片之间的默认质检间距为 8mm。
- 旧的 580mm 默认已经被后续膜规格要求取代。
- 不单独设置左右图片边距来重复 RIIN 自带的边距功能。
- 上下留白的 UI 名字要明确，例如“批次开头与结尾留白”，不能笼统叫上下边距。
- 在物理安全约束和订单组约束下节省材料，不能为省膜破坏生产顺序。
- 显示智能排版/旋转相比基准排版缩短多少米；必须比较实际完整批次长度。

## 7. 固定刀位、分区和色块

- 色块默认正红色 `#ff0000`，正方形 10mm × 10mm。
- 色块尺寸、颜色、间距、位置应可设置并实时预览，参数放在打印参数中。
- 色块在“分区所能识别的固定左边缘”，不是跟着每张图片左侧移动。
- 左分区色块固定在膜左边缘识别区；右分区也需要色块，固定在第二刀对应的左边缘基准。
- 左右图片不得跨越固定纵向刀位或安全通道，标签及色块也不能侵入通道。
- 常规区域的刀位整区保持同一条直线，不要求在膜宽的一半。
- 自动刀位要按整个区域/批次的全部图片计算，不得每两张图片重新换一次。
- 用户可关闭自动刀位，手动调整并查看真实预览。
- 输出中必须保留完整分区坐标基准；不能裁边、居中或挪动图片导致刀位失效。
- 排版前检查所有图片和标记坐标；合成后再检查安全通道实际像素透明。
- 检查失败禁止输出可打印结果，不允许为显示预览而绕过生产检查。

## 8. 旋转区域（最新确认的规则）

- 图片可手动左旋、右旋、还原；默认旋转方向为向左。
- 原“切膜模式一律不允许旋转”已被以下分区规则取代，不能简单恢复全局禁止。
- 常规区和旋转区使用各自独立的固定刀位。
- 从常规区进入旋转区时允许调整一次刀位；同一个区域中不能持续移动刀位。
- 旋转区同一水平行只能放一张图片，不允许两张并排。
- 多件订单和双面图片必须作为完整订单组进入旋转区，并保持组内相邻。
- 加上区域边界和间距之后，仍比不分旋转区更省材料，才自动启用旋转区。
- 若不能减少整批用膜，保持原常规排版，不为旋转而旋转。
- 预览明确显示区域名称、各区刀位、贯穿安全通道和换刀位置。
- 批次记录保存每张图所在区域及其实际刀位，不能只保存一个模糊的全局刀位。

## 9. 标签和文字

- 用户标签示例：`CY 1001Mt______26`，多余的连续下划线要移除。
- 机器号为大写 `M1` 至 `M11`，支持选择并保存，也可加入标签文字。
- 默认中文六号字，即 7.5 磅，不是 6mm 或 6 磅。
- 支持修改文字内容、字号、位置、间距、微调及添加日期。
- 用户强调文字不能大到影响剪膜，也不能小到肉眼看不清。
- 标签应与对应色块组成标记组，不能一个跟二维码走、另一个留在其他位置。
- 原要求：识别生产图中膜标签的实际区域，整段文字（含换行）与它等高，并限制宽度。
- 不能把二维码中心或二维码高度直接冒充整条膜标签高度；不能用默认 10mm 猜测。
- 自动适配要测量真实字形和整段文字，必要时换行，不能拉成长条增加排版长度。
- 识别失败应明确提示，不悄悄猜位置、猜字号或挡住二维码、图案。
- 后续明确的切膜要求：标记组在分区左边缘，文字贴近色块，默认六号字。
- 两者的优先级：切膜分区与标记组安全位置优先；自动膜标签适配不能把标签移出标记组。
- 若等高、限宽、可读字号不能同时满足，应提示冲突，不可悄悄缩到看不见。
- 生产图片旋转时要重新适配参考区域；文字保持正向，色块仍在分区固定左边缘。

## 10. 预览、生成、停止及输出

- 默认显示整批总览，可滚动查看全部图片，而不只是两个样本。
- 保留双图细节视图，便于检查左右图片、标签、色块及刀位。
- 预览使用实际排版数据，与输出位置、旋转和刀位一致，不画虚假的安全示意图。
- 参数变化自动刷新；连续联动的中间状态应合并刷新。
- 参数不安全时仍显示图片，标红越界区域，并明确“仅供检查，禁止输出”。
- 读取/刷新失败不能无说明变成白屏，错误信息必须可见。
- 生成新批次时清除旧批次预览、缩略图、错误和旧数据，显示加载状态。
- 新排版数据到达后立即替换；不能把旧批次图片和新批次进度混在一起。
- 生成过程中能看实际排版预览；保存大图期间保留本次预览并显示持续写入状态。
- 必须有停止功能，保存阶段安全停止，不能破坏已经写完的文件。
- 输出文件名取标签文字，例如 `CY 1001Mt26.png`，不能固定叫 `print.png`。
- 日期/机器号等模板变量先展开，非法文件名字符安全处理。
- 重名不能覆盖旧图；新生成批次不能覆盖旧批次。
- 保存进度、完成提示和批次记录必须使用真实输出文件名。

## 11. 大文件、并发和 Qt 线程

- 允许图片处理并行，但并发受内存限制，不能一次加载整批原图。
- 测试尽量用少量文件，避免因大量图片让测试过慢。
- 预览使用缩略图和有界缓存，整批总览按需读取可见图片。
- 大 ZIP 和原始图片不上传，ZIP 同样太大。
- 下载并行，使用浏览器原生流式传输，不能把多个 ZIP 全部放进内存。
- Qt 控件、QTextDocument、预览绘制只在 GUI 线程操作。
- 不跨线程 setParent、installEventFilter，不在工作线程直接更新 UI。
- QPainter 显式结束，工作对象/线程按正确生命周期清理，不能销毁仍在运行的 QThread。

## 12. ERP 功能（保留需求，当前隐藏）

- 平台至少包括 Haloo（蜂鸟）和隆丰；Haloo 为默认平台，其他平台不能凭空猜名单。
- 订单进入 ERP → 已接单 → 按物流分拣 → 按单多件规则生成生产批次 → 等待图片生成 → 下载。
- 批次生成不可撤销，只有一次机会；必须展示规则、数量及异常项，再确认生成。
- 物流第一优先级，然后才是单项单件、单项多件、多项多件。
- Haloo 物流分类包括 UPS、FedEx、Swift、USPS、Gofo、Yanwen、SpeedX。
- `spee` 属于 SpeedX，不能当作无法分类物流排除。
- CBT / 非 CBT 是隆丰物流规则，不是 Haloo 规则。
- 单件中的双面要单独识别并展示数量。
- 无法按规则生成的异常订单单独提出，不应阻止其他正常订单生成。
- 生成弹窗支持“按有面单生成批次”。
- 平台页名称为“已接单”和“生产批次”；已清单页已要求移除。
- 已接单显示尚未进入生产的订单数量，未进入生产的数量标红。
- 生产批次不应读取已接单 API；平台和批次数据缓存，真正需要时才刷新。
- 登录成功自动进入该平台子域名的 `factory/fnsz-sale/produceManage/produceItemsManage`。
- 复用 after-sales 的 Playwright 相关实现，登录后优先 API，避免慢速逐步网页操作。
- 支持全选、批次号范围下载（示例 `607250635009`–`607250652014`）及并行下载。
- 本地已经有文件时不重复下载，本地排版不依赖重新访问生产接口。
- 支持几个批次的图片合并排版。
