# 真实批次回归矩阵

本文件记录当前用于排版回归的真实本地批次。每个批次独立完成“仅预览复现、问题修复、
针对性测试、同批次复测、单独推送”；默认不生成生产大图。表中结果是当前有效事实，
不是聊天记录。

## 完整测试固定范围

“完整测试”不等于只运行完整自动测试套件。每次完整测试还必须从本机现有真实文件中选择不同
生产平台的代表批次，至少包含本次受影响平台和另一种文件结构不同的平台。可用时覆盖隆丰、
S2B、Haloo及其他已接入平台；某个平台暂无样本时继续测试其他平台，并在结果中明确标记未覆盖，
不得把单平台结果称为完整测试。

每个真实批次必须同时核验：

- 标签和二维码卡片区域没有遮挡生产内容，标签关闭时也不影响刀码；
- 左侧识别刀码、右侧分割刀码和全部纵向刀位与实际排数一致；
- 图片旋转后，标签、二维码区域和刀码方向同步且位置正确；
- 单件、多件、双面和订单连续性符合平台规则；
- 预览数据、排版坐标、实际输出像素及输出文件信息相互一致。

## 本地固定验收矩阵

`windows/real-batch-suite.json` 保存本地可复现矩阵和预期图片数。数据由
`windows/stage-real-batch-suite.ps1` 从 NAS 只读复制到本地 staging；运行时记录实际 Git commit 和
输入文件清单摘要。矩阵至少包含十个独立批次文件夹：三个 Haloo 批次使用固定种子 `20260917`
选取，另含各两个隆丰、莆田和 S2B 完整批次，以及下述隆丰性能批次。
隆丰 `609172109020` 必须对全部200张 PNG 分别执行冷、热缓存完整生成，8段并行输出均不得超过30秒。
每批独立保存输出、日志和 JSON 报告；失败不阻断后续批次，但整个任务最终失败。此流程不接单、
不写入源图、不导入打印软件，也不触发物理打印。
