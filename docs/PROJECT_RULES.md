# Project Rules

## 产品标准

- 本项目是实际生产工具，不是一次性脚本。生产安全、可恢复性和可解释性优先于局部省膜或跑分。
- 参数、膜规格、平台和机器差异应配置化；不得把当前工厂的临时测试值扩散成通用常量。
- 兼容已保存参数、缓存、输出报告和测试电脑更新流程；行为改变需有迁移或明确降级。
- 失败必须面向用户说明具体订单、文件、原始参数、限制参数、失败步骤和程序采取的处理。

## 结构

- Python 文件通常为 100–200 行。普通控制器和组件默认不超过 200 行。
- 新的单一业务子包最多保留5个直接实现模块；超过时先按领域继续分层，禁止用大量平铺文件充当分类。
- 遗留超长文件只允许保持或缩小；修改其职责时优先抽取到已有功能目录。
- 依赖方向固定为 UI → 控制器 → 领域/持久化；控制器不得导入 Qt Widgets，领域与持久化不得读取页面控件。
- `automatic_print/ui/` 只拥有 Qt 控件、展示模型、交互状态和 GUI 线程适配。
- `automatic_print/controllers/` 只拥有用例编排、任务生命周期、取消和进度计算。
- `automatic_print/layout_engine/` 拥有纯排版、测量、订单、刀位、旋转、渲染和输出校验。
- `automatic_print/history/` 拥有运行记录、历史查询和持久化历史数据。
- `automatic_print/automation/api/<provider>/` 拥有外部 ERP 的认证、请求、分页与平台解析。
- 主窗口、对话框和入口文件只负责编排，不承载图片算法、平台请求、缓存格式或报告计算。
- 相同业务能力只有一个规范所有者。兼容模块只能转发，不得包含第二套业务逻辑。
- DRY 用于消除同一业务规则和副作用的重复所有者；KISS 用于拒绝无行为价值的抽象层。仅为减少行数而拆分、
  为外观相似而错误复用、或为未来假设预建框架都不允许。

## 复用门禁

新增 helper、服务、缓存、验证、状态组件或平台适配器之前必须：

1. 在 `FUNCTION_CATALOG.md` 确认已有所有者。
2. 按输入字段、输出字段、中文文案、数据类型和测试搜索活动调用方。
3. 优先组合已有能力，再扩展接口，再抽共享核心并迁移全部活跃重复。
4. 只有业务输入、输出、副作用或安全语义确实不同，才新增实现。
5. 新增共享能力后补目录登记和共享边界测试。

外观相似不代表可以错误复用；反过来，名称不同也不能成为复制相同算法的理由。

## UI 与并发

- 所有新增产品功能默认只在开发者模式出现并生效；只有用户明确要求移出开发者模式后，才能进入普通
  生产界面和默认生产调用链。
- UI 按操作顺序和父子层级组织：入口与常用参数、批次状态与结论、真实预览、详细检查、低频设置。
- 相关功能放在一个区域；不同完整流程使用聚焦视图或标签页，避免堆叠多个大表和表单。
- 结论、风险、当前批次和当前膜优先展示；计算细节和开发诊断放后面。
- 相同信息不在多个位置重复；所有用户需要复制的问题、状态和诊断使用可复制文本。
- 已知工作量显示真实进度，未知工作量显示旋转状态；不能用假的百分比安慰用户。
- 并行只用于互不依赖的读取、测量、方案或批次任务。共享刀位、订单顺序、有序合成和单文件编码
  不得伪装为完全并行；线程池有空位即补充下一任务。
- Qt 控件只在 GUI 线程操作。停止采用可控取消，窗口关闭可立即终止，但不能留下可误打印的半成品。

## 变更和验证

- 先读活动调用链和测试，再做最小完整修改；允许为消除当前重复进行直接相关重构。
- 日常修改默认只运行本次调用链直接相关的局部测试，优先让用户立即拿到可测试源码。运行完整测试
  套件前必须先询问用户并取得明确同意，不得自行用完整测试延迟交付。
- 缓存必须有版本、输入指纹和失效规则；不得让旧参数或旧文件结果污染新批次。
- 生产输出必须验证来源数量、订单连续、双面相邻、尺寸/DPI、刀位通道、标记位置和输出文件头。
- 针对性测试证明本次逻辑；完整代表批次证明生产事实。测试通过不等于切膜机实物验收。
- 当前推送门禁以本次调用链的局部测试为准，不要求完整测试；只有用户明确要求时才运行完整测试。
  已运行的局部测试失败时仍禁止推送，必须先修复并重新验证相关范围。
- GitHub 的 `Quality Gate` 在 Windows/Python 3.12 运行完整测试；`main` 应启用分支保护并要求该检查
  通过。自动检查用于补充本地局部验证，不得阻塞用户要求的及时源码推送。
- Release 还必须验证 Windows 构建、启动、更新及安装包；源码更新不是 Release。

## 文档

- 业务规则变化覆盖 `BUSINESS_RULES.md` 中的现行规则，不追加版本章节。
- 模块移动或所有权变化更新 `CURRENT_STATE.md`。
- 共享接口新增、迁移或删除更新 `FUNCTION_CATALOG.md`。
- 稳定工程偏好才更新本文。提交历史、版本次数和一次性测试结果留在 Git 和提交记录中。
